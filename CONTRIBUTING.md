# Contributing to ShopApp

Thank you for considering contributing to ShopApp! We welcome contributions from the community to help improve this ERP system.

## Code of Conduct

Please note that this project is released with a Contributor Code of Conduct. By participating in this project you agree to abide by its terms.

## How Can I Contribute?

### Reporting Bugs

Before creating bug reports, please check the existing issues as you might find out that you don't need to create one. When you are creating a bug report, please include as many details as possible:

- Use a clear and descriptive title
- Describe the exact steps which reproduce the problem
- Provide specific examples to demonstrate the steps
- Describe the behavior you observed after following the steps
- Explain which behavior you expected to see instead
- Include screenshots if possible

### Suggesting Enhancements

Enhancement suggestions are tracked as GitHub issues. When creating an enhancement suggestion, please include:

- A clear and descriptive title
- A detailed description of the proposed enhancement
- Explain why this enhancement would be useful
- List some other ERP systems where this enhancement exists

### Pull Requests

- Fill in the required template
- Do not include issue numbers in the PR title
- Include screenshots and animated GIFs in your pull request when possible
- Follow the JavaScript/JSX styleguides
- Include thoughtfully-worded, well-structured tests
- Document new code based on existing documentation style
- End all files with a newline

## Styleguides

### Git Commit Messages

- Use the present tense ("Add feature" not "Added feature")
- Use the imperative mood ("Move cursor to..." not "Moves cursor to...")
- Limit the first line to 72 characters or less
- Reference issues and pull requests liberally after the first line

### JavaScript Styleguide

All JavaScript code should follow the Airbnb JavaScript Style Guide with the following exceptions:

- Use 2 space indentation
- Prefer single quotes over double quotes
- Allow for...in statements without hasOwnProperty
- Allow anonymous functions

### React/JSX Styleguide

All JSX code should follow the Airbnb React/JSX Style Guide with the following exceptions:

- Use functional components over class components
- Use React Hooks where appropriate
- Prefer function declarations for components

## Development Setup

1. Fork the repository
2. Clone your fork
3. Create a new branch for your feature or bug fix
4. Install dependencies for both frontend and backend
5. Make your changes
6. Write tests if applicable
7. Ensure all tests pass
8. Commit your changes
9. Push to your fork
10. Create a pull request

## Testing

- All new features should include appropriate tests
- Run the full test suite before submitting a pull request
- Ensure all tests pass in all supported Node.js versions
